Esta guía te muestra cómo construir un pipeline de procesamiento de archivos usando **AWS S3**, **Lambda** y **DynamoDB** localmente con **AWS Emulator**, el emulador local oficial de AWS, y **Python**. Este lab demuestra cómo las subidas a S3 disparan una Lambda para registrar metadatos en una tabla DynamoDB.

## Prerrequisitos

- [Docker](https://www.docker.com/get-started) instalado y en ejecución.
- [Dev Containers extension](vscode:extension/ms-vscode-remote.remote-containers) instalada (opcional).
- [AWS Toolkit para VS Code](vscode:extension/amazonwebservices.aws-toolkit-vscode) (opcional, incluido en el Dev Container).

## Cómo ejecutar

Ejecuta todos los scripts a través de **mise**: `mise run <tarea>` carga `.env`, elimina del entorno cualquier credencial real de AWS y pone las herramientas del lab en el `PATH`.

1. **Prepara el entorno**:
   <Tabs>


      </TabItem>
   </Tabs>

</Steps>


## Cómo depurar

1. **main.py**:
   - **Abre**: Abre `main.py`.
   - **Breakpoints**: Pon breakpoints en el código.
   - **Ejecuta**: Pulsa `F5` para empezar a depurar.

2. **Tests**:
   - **Abre**: Abre `tests/test_file_pipeline.py`.
   - **Breakpoints**: Pon breakpoints en el código del test.
   - **Ejecuta**: Usa la pestaña **Testing** de VS Code y haz clic en el icono **Debug Test** junto al test.

## Cómo testear

Los tests despliegan su propio pipeline (nombres en `.env.test`) y lo eliminan al terminar.

- **Individualmente**: Ejecuta los tests uno a uno desde la pestaña **Testing** de VS Code.
- **Todos los tests**: Ejecuta el script automatizado:
  ```bash
  mise run test
  ```

## Validar resultados

<Tabs>
   <TabItem label="AWS CLI">
      - **Verifica** que la AWS CLI llega al emulador (cuenta `000000000000`):
        ```bash
        mise exec -- aws sts get-caller-identity
        ```
      - **Comprueba el bucket S3**:
        ```bash
        mise exec -- aws s3 ls s3://file-uploads-bucket
        ```
      - **Escanea la tabla DynamoDB**:
        ```bash
        mise exec -- aws dynamodb scan --table-name file-logs
        ```
      - **Consulta los logs de Lambda**:
        ```bash
        mise exec -- aws logs tail /aws/lambda/s3-file-processor
        ```
   </TabItem>
   <TabItem label="AWS Toolkit">
      En el Dev Container, AWS Toolkit usa el perfil `default` que AWS Emulator escribe en `.aws/emulator/`.
      - **Conecta**: Selecciona el perfil `default` y la región `us-east-1` en AWS Toolkit.
      - **S3**: Despliega la sección S3 para ver los archivos subidos.
      - **CloudWatch**: Despliega la sección Logs para ver la salida de ejecución de Lambda.
   </TabItem>
</Tabs>

```bash

```

## Solución de problemas

| Problema | Solución |
|----------|----------|
| `Could not connect to the endpoint URL` o errores SSL | Ejecuta los comandos de la AWS CLI con `mise exec -- aws ...` desde la raíz del lab, para que carguen `.env`, y comprueba que el emulador está sano con `docker compose ps`. |
| `AccessDenied: Sign the request with the emulator credentials` | Las credenciales reales de AWS de tu entorno tienen prioridad. Ejecuta los comandos con `mise run` o `mise exec`, que las eliminan. |
| Los recursos han desaparecido | AWS Emulator guarda los recursos en memoria, así que un reinicio los borra. Vuelve a desplegar. Con Terraform, borra antes `deploy/terraform/terraform.tfstate`. |
| La Lambda no se dispara | Revisa los logs con `mise exec -- aws logs tail /aws/lambda/s3-file-processor`. Como AWS, el emulador comprueba el rol de la Lambda, así que un `AccessDenied` ahí indica un permiso que falta en la política del rol. |
| AWS Toolkit no conecta tras un reinicio | El emulador crea un certificado nuevo en cada arranque. Ejecuta **Developer: Reload Window** en VS Code. |
